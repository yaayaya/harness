Harness 是一个 meta-skill。你只要提供领域描述，它就会帮你设计代理人团队、定义专职 agent，并产生这些 agent 会用到的技能。

这个繁中入口版本包含什么？

目前采用低维护成本的「路线 A」：保留原始英文内容为主体，新增繁中入口文件，避免未来同步上游时产生大量冲突。

  • 新增 `README_ZH_TW.md`，作为主要繁中说明入口。
  • 新增繁中首页与繁中隐私页。
  • 保留原本 `skills/` 与 `references/` 的英文内容，后续可再逐步翻译。

Harness 是做什么的？

它会把「这个专案需要什么样的代理人协作方式」这件事系统化。输入一句领域需求，就能自动产出 `.claude/agents/` 与 `.claude/skills/` 的骨架与流程。

设计

代理人团队设计

内建 6 种团队模式，像是 Pipeline、Fan-out/Fan-in、Producer-Reviewer、Supervisor 等。

生成

技能自动生成

依据你的领域描述，帮每个 agent 产出对应的技能结构与参考文件配置。

验证

验证与迭代

包含验证、dry-run，以及使用 skill 与未使用 skill 的比较思路，方便后续演进。

6 阶段工作流

Harness 的主要输出流程分成六个阶段，适合拿来快速建立一套可持续维护的代理人团队结构。

第 1 阶段

领域分析：先理解专案领域、工作类型与任务边界。

第 2 阶段

团队架构设计：决定该用 Agent Teams 还是 Subagents，以及采用哪种协作模式。

第 3 阶段

产生代理人定义：建立 `.claude/agents/` 内的角色定义。

第 4 阶段

产生技能：建立对应的 `.claude/skills/` 与参考资料。

第 5 阶段

整合与协调：安排资料传递、审查点与工作流程串接。

第 6 阶段

验证与测试：验证输出是否可用，并为下一轮演化留下基础。

安装方式

如果你已经在使用 Claude Code，可以直接用 Marketplace 安装，或把 skill 目录复制成全域 skill。

/plugin marketplace add revfactory/harness /plugin install harness@harness

后续同步建议

这份繁中化采取入口文件分离策略，后续若要追原作者更新，建议把上游更新先合到主分支，再视需要同步调整繁中 README。

main 追上游 translation branch 放繁中调整 README_ZH_TW.md 尽量独立维护

下一步可以怎么做？

如果你觉得这份入口文件够用了，下一阶段就可以开始评估是否要翻译 `skills/harness/SKILL.md` 与 `references/`，那会是功能层面的深度翻译版本。
