代理人團隊

Harness 是一個 meta-skill。你只要提供領域描述，它就會幫你設計代理人團隊、定義專職 agent，並產生這些 agent 會用到的技能。

閱讀繁中 README GitHub 原始專案

這個繁中入口版本包含什麼？

目前採用低維護成本的「路線 A」：保留原始英文內容為主體，新增繁中入口文件，避免未來同步上游時產生大量衝突。

  • 新增 `README_ZH_TW.md`，作為主要繁中說明入口。
  • 新增繁中首頁與繁中隱私頁。
  • 保留原本 `skills/` 與 `references/` 的英文內容，後續可再逐步翻譯。

Harness 是做什麼的？

它會把「這個專案需要什麼樣的代理人協作方式」這件事系統化。輸入一句領域需求，就能自動產出 `.claude/agents/` 與 `.claude/skills/` 的骨架與流程。

設計

代理人團隊設計

內建 6 種團隊模式，像是 Pipeline、Fan-out/Fan-in、Producer-Reviewer、Supervisor 等。

生成

技能自動生成

依據你的領域描述，幫每個 agent 產出對應的技能結構與參考文件配置。

驗證

驗證與迭代

包含驗證、dry-run，以及使用 skill 與未使用 skill 的比較思路，方便後續演進。

6 階段工作流

Harness 的主要輸出流程分成六個階段，適合拿來快速建立一套可持續維護的代理人團隊結構。

第 1 階段

領域分析：先理解專案領域、工作類型與任務邊界。

第 2 階段

團隊架構設計：決定該用 Agent Teams 還是 Subagents，以及採用哪種協作模式。

第 3 階段

產生代理人定義：建立 `.claude/agents/` 內的角色定義。

第 4 階段

產生技能：建立對應的 `.claude/skills/` 與參考資料。

第 5 階段

整合與協調：安排資料傳遞、審查點與工作流程串接。

第 6 階段

驗證與測試：驗證輸出是否可用，並為下一輪演化留下基礎。

安裝方式

如果你已經在使用 Claude Code，可以直接用 Marketplace 安裝，或把 skill 目錄複製成全域 skill。

/plugin marketplace add revfactory/harness /plugin install harness@harness

後續同步建議

這份繁中化採取入口文件分離策略，後續若要追原作者更新，建議把上游更新先合到主分支，再視需要同步調整繁中 README。

main 追上游 translation branch 放繁中調整 README_ZH_TW.md 盡量獨立維護

下一步可以怎麼做？

如果你覺得這份入口文件夠用了，下一階段就可以開始評估是否要翻譯 `skills/harness/SKILL.md` 與 `references/`，那會是功能層面的深度翻譯版本。
